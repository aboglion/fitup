## 2. Findings (by severity)

### 🟠 MODERATE — M1: Stale user-visible version strings (v15.7 vs v15.9)

The authoritative runtime program version is **`"15.9 Accelerated"`** ([`js/data.js`](js/data.js:1), generated by `generate_program.py`), and the guides already say **v15.9** — but several user-visible About/UI texts still say **v15.7**:

| Location | Current text |
|---|---|
| [`js/i18n.js`](js/i18n.js:444) `about_desc` (EN) | "FitUp Pro v15.7 Accelerated" |
| [`js/i18n.js`](js/i18n.js:2058) `about_desc` (HE) | "FitUp Pro v15.7 Accelerated" |
| [`js/i18n.js`](js/i18n.js:3828) `about_desc` (AR) | "FitUp Pro v15.7 Accelerated" |
| [`js/i18n.js`](js/i18n.js:1339) `lean_program_title` (EN) | "v15.7 Accelerated Program" (HE `:2905`, AR `:4289` same) |
| [`js/stats.js`](js/stats.js:983) | Badge `Active v15.7` |
| [`about.html`](about.html:193) | "FitUp Pro v15.7 Accelerated" (also `:200`, `:234`) |
| [`index.html`](index.html:1123) | Fallback `about_desc` text "v15.7" |
| [`README.md`](README.md:1) | Title "v15.7 Accelerated" — **but** [`README.md`](README.md:166) contains a "v15.9 Accelerated Architecture" section (internal contradiction) |

**Impact:** Cosmetic but user-facing; inconsistent brand/version identity across UI, docs, and generated guides.
**Recommended fix:** Bump About/badge/README strings to `v15.9 Accelerated` to match `TRAINING_DATA.version`, the export guide, and `PROGRAM_GUIDE.md`.

### 🟡 LOW-MODERATE — M2: PWA precache gaps (cold-offline first-run)

[`sw.js`](sw.js:3) `ASSETS` precache list is missing 4 files that the app references:

1. **`js/program-guide-content.js`** — loaded by [`index.html`](index.html:1301) (`window.PROGRAM_GUIDE_TEXT`) but **absent** from the SW precache (confirmed: it's the *only* JS on disk not in the list; 25 of 26 cached).
2. **`about.html`**, **`privacy.html`**, **`terms.html`** — navigation pages not precached.

**Impact:** Low in practice (the SW is Network-First, so these get cached after the first successful online visit; offline fallback uses `ignoreSearch`). But on a **cold install while offline**, the Program Guide modal and the three legal/info pages would fail to load.
**Recommended fix:** Add the 4 paths to the `ASSETS` array in `sw.js` and bump `CACHE_NAME`.

### 🟡 LOW — M3: `make test` does not run the three comprehensive audit scripts

[`Makefile`](Makefile:3) `test` target runs `check.py`, `check_mismatches.py`, `node --test tests/*.test.js`, and `deep_audit.js` — but **not** [`full_system_audit.js`](tests/full_system_audit.js), [`microscopic_audit.js`](tests/microscopic_audit.js), or [`ultra_deep_audit.js`](tests/ultra_deep_audit.js). These scripts caught the legacy-name warnings and DOM checks and should be part of CI.
**Recommended fix:** Append `node tests/full_system_audit.js && node tests/microscopic_audit.js && node tests/ultra_deep_audit.js` to the `test` target.

### 🟡 LOW — M4: Legacy exercise names in anatomy modal lists

[`full_system_audit.js`](tests/full_system_audit.js) reported 11 info-warnings: [`js/anatomy.js`](js/anatomy.js) modal muscle lists still reference 10 names not used in the current program (e.g. `Diamond Push-Up`, `Chin-Up Progression`, `Wall Sit`, `Single-Leg Glute Bridge` under several muscles).
**Impact:** Informational — these are fallback/lookup lists; the in-program entries resolve correctly. Cleanup recommended to avoid stale-data confusion.
**Recommended fix:** Prune or alias the legacy names in `anatomy.js` so the modal lookups reflect the 59 active exercises.

### 🟢 INFORMATIONAL — N1: Push:Pull volume ratio 0.89

[`full_system_audit.js`](tests/full_system_audit.js) reports `Push : Pull = 2821 : 3163 → 0.89`, below the flagged ideal band (0.95–1.05). This is a design-level observation (Pull-biased V-taper emphasis is intentional per the product brief), not an error.
**Recommended review:** Confirm the intentional pull bias; if a 1:1 balance is desired, a small push-volume addition would be needed.

### 🟢 INFORMATIONAL — N2: Unused/backup media inventory

- `images/exercises/` contains **119 PNGs**; ~43 have no direct name match to the 59 program exercises (mostly alias variants / legacy media) and there is a full `images/exercises_original_backup/` directory and a `generate_program.py` placeholder-copy path.
- **Impact:** Storage bloat only. All 59 program exercises resolve to valid images (0 missing).
**Recommended action:** Optionally prune the backup/legacy PNG set (or move it out of the app shell) to shrink PWA install size.

### 🔵 TRIVIAL — N3: Documentation polish

- [`README.md`](README.md:3): *"**A** 80-Week"* → should be *"**An** 80-Week"* (grammar).
- [`js/today.js`](today.js:144): comment references `(v15.7.2)` — no such release marker exists (db schema marker is `15.7.1` at [`js/db.js`](js/db.js:1248)). Comment-only inconsistency.

## 3. Items Deliberately NOT Changed (intentional design)

- [`js/app.js`](js/app.js:342) `currentDataVersion = '15.7.0'` — left as-is **on purpose** by the v15.7.1 patch plan: bumping it would trigger `clearTracking()` and wipe user tracking data. Re-seeding flows through the db.js marker (`15.7.1`) instead. ✅ Correct, do not "fix".
- `armBlock.enabledFromWeek: 3` (micro-dosing) vs export-guide "Active from Week 6" (full cluster) — **consistent**: data.js defines a ramp (`W3: 1+1×4 → W4–5: 1+2×4 → W6+: 1+3×5`); the guide describes the full cluster. No conflict.
- English/Arabic/Hebrew all default to **Sunday-first** week (Israeli-microcycle product decision) — consistent across UI, calendar, and combat scheduler tests.
